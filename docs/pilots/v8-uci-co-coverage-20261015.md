# V8 Pilot 3 — UCI Air Quality: drift and delayed interval calibration (2026-10-15)

## Fixed research question

Using real-world hourly gas sensor readings, test whether a rolling residual-calibration strategy with explicitly delayed reference-analyzer feedback achieves more stable empirical 90% uncertainty-interval coverage than a frozen static-calibration strategy under possible temporal drift. Evaluate interval width, coverage and accuracy without assuming the adaptive strategy wins. This is NOT PFL3, FlyCX, cold rolling, future-hour forecasting or an assertion of distribution-free drift robustness.

Data source: UCI Air Quality dataset ID 360, DOI 10.24432/C59K5F, https://archive.ics.uci.edu/dataset/360/air+quality . Official description reports approximately 9,358 hourly examples, gas sensors, reference analyzer readings, temporal drift and a -200 missing sentinel. Operator-staged input/AirQualityUCI.csv and input/SOURCE.json are authoritative local *bytes* with input/PROVENANCE.json hashes, not proof of an authentic upstream release or correct processing. Academic research only.

## Scope and information boundary

1. Target: same-hour certified analyzer CO(GT), units mg/m^3. Available operational features may include the five PT08.* sensor channels, temperature, relative humidity, absolute humidity, and declared time-of-day/calendar features. The estimator predicts current-hour CO from current-hour sensors; DO NOT call it future forecasting.
2. No reference-analyzer (GT) columns may appear as model features, proxies, normalization statistics at the wrong time, or inputs at test time. Other GT columns are forbidden even when correlated with the target. A 24-hour delay is ASSUMED before a test CO(GT) reference label can enter a rolling calibration history. At time t, only labels observed at times <= t minus 24 hours can update the interval. Missing labels cannot enter calibration or evaluation.
3. Inspect the actual raw CSV schema before interpreting it; common hazards are semicolon-separated fields, comma decimals, day/month/year dates, extra blank separators, duplicate timestamps and -200 sentinel entries. Document genuine missingness and sensor outages. Never convert -200 into physical values, silently drop missing hours to optimize the split, or call operator-staged provenance independent upstream authenticity.
4. Freeze the chronological train / calibration / untouched final evaluation boundaries **over timestamps**, before selecting models by evaluation results. Suggested 60% development / 20% calibration / 20% final evaluation. Record cutoffs and evidence that training, preprocessing and static calibration never access later labels. Do not shuffle windows or tune on the final evaluation set.
5. Choose a small reproducible sensor-only point prediction baseline and a simple multichannel predictor using current-hour permitted features. Prefer standard library and installed packages, not heavyweight neural networks or unbounded search. Tune any model variants using only development data.
6. On the SAME frozen point predictions compare static two-sided nominal-90% residual prediction intervals versus rolling windows updated only with the 24-hour delayed reference feedback. Choose window, quantile definition and missing-sample handling before opening final test outcomes. Do not claim exchangeable conformal coverage guarantees under temporal drift.
7. Report independent evaluator counts, point MAE, empirical interval coverage, mean width, and sensible temporal slices. A block-aware or otherwise time-aware uncertainty/sensitivity analysis is permitted when necessary and affordable. Pair comparisons properly. State when an improvement is not supported and explicitly distinguish conditional empirical performance from deployment claims.
8. Independent verification must test for label leakage, chronological leakage, parsing defects, delayed-feedback violations, math/report inconsistency, input mutation and fake execution evidence. Reviewer chooses minimum sufficient typed required_checks in the exact approved protocol; if a separate Python checker is needed, it can be named in checker_execution.checker_path. Host PASSED is execution/data integrity only; Reviewer determines scientific adequacy.
